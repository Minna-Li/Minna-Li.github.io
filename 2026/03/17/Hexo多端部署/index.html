Hexo 博客多端 / 新设备部署与同步指南

本指南涵盖了在强管控网络（如公司内网）或全新设备上，从零搭建环境、拉取源码、修复主题同步坑点，到日常多端协作的完整流程。

一、 环境准备（Git & Node.js）

1. 安装 Git & 配置凭证保存

  • 下载并默认安装 Git。
  • 为了在 HTTPS 下实现免密推拉代码，在 Git Bash 中运行一次凭证保存，让 Git 记住你的 GitHub 账号密码 / Personal Access Token（个人访问令牌），避免每次 push 或 pull 都让你手动输入：
    git config --global credential.helper store

2. 安装 Node.js

  • 访问 Node.js 官网，下载 LTS 版本 (.msi 安装包)。
  • 它的作用是：让 JavaScript 可以在你的电脑系统里直接运行, 电脑必须安装了 Node.js 这个“发动机”，才能看得懂 Hexo 的代码，才能把你的 .md 文章渲染拼装成 .html 网页
  • npm 的全称是 Node Package Manager（Node 包管理器）, 下载安装 Node.js 时，它会自动附带安装好 npm
  • 安装注意：在安装向导中，切勿勾选 “Automatically install the necessary tools (Chocolatey)” 选项（避免下载无用工具及内网卡死），直接点击 Next 到底完成安装。
  • 重启终端：关闭并重新打开 Git Bash，验证安装（显示版本号即安装成功）：
    node -v
npm -v

二、 配置公司网络代理（内网环境必看）

在受限网络下，建议使用 HTTPS + 代理 方案（比 SSH 方案更兼容内网防火墙）。

1. 配置 Git 代理

# 设置 Git 走公司 HTTP 代理（按实际代理地址修改）
git config --global http.proxy [http://proxy-server.com:8080](http://proxy-server.com:8080)
git config --global https.proxy [http://proxy-server.com:8080](http://proxy-server.com:8080)
# 让 Git 信任代理网络的 SSL 证书
git config --global http.sslVerify false

2. 配置 npm 代理

npm config set proxy [http://proxy-server.com:8080](http://proxy-server.com:8080)
npm config set https-proxy [http://proxy-server.com:8080](http://proxy-server.com:8080)
npm config set strict-ssl false

btw，如果回家/断开公司网： 记得把代理清除掉（把 set 改成 delete 或 unset），否则在家反而会上不了网。

三、 拉取源码与环境恢复

1. 克隆博客源码仓库

git clone [https://github.com/你的用户名/博客源码仓库名.git](https://github.com/你的用户名/博客源码仓库名.git)
cd 博客源码仓库名

2. 安装项目依赖

npm install

常见问题：若执行 git pull 时提示 package-lock.json 冲突被打断，可丢弃本地生成的该文件改动后重新拉取：

git checkout -- package-lock.json
git pull origin main

四、 主题（Butterfly）与插件踩坑修复

1. 解决主题文件夹拉取后为空的问题（私人电脑侧操作）

由于主题文件夹内可能包含原作者的 .git 隐藏目录，Git 会将其识别为“子模块”而跳过文件上传。需在旧设备上执行以下清理操作并重新上传：

# 1. 移除主题内的隐藏 .git 目录
rm -rf themes/butterfly/.git

# 2. 清除 Git 底层对其作为“子模块”的旧缓存
git rm --cached themes/butterfly

# 3. 重新添加主题文件并提交上传
git add themes/butterfly
git commit -m "add complete butterfly theme files"
git push origin main

2. 安装 Butterfly 必需的渲染插件（新设备侧操作）

Butterfly 主题模版依赖 Pug 和 Stylus 解析器，新设备恢复依赖后必须补全安装：

npm install hexo-renderer-pug hexo-renderer-stylus --save

五、 本地预览与 npx 解析

运行以下命令启动本地预览服务：

npx hexo clean && npx hexo g && npx hexo s

为什么推荐使用 npx hexo？
npx 会优先调用当前博客根目录下 node_modules 中安装的本地 Hexo 版本，无需在系统全局安装 hexo-cli，既能防止环境污染，又能确保多台电脑构建效果 100% 一致。

浏览器访问 http://localhost:4000 检查无误后，按 Ctrl + C 可关闭服务器。

六、 多端协同日常工作流

在多台电脑（如私人电脑与工作电脑）轮流写博客时，请遵循 “先拉取，后写作，再同步” 的原则：

# 1. 写作前：拉取云端最新源码（防止版本冲突）
git pull origin main

# 2. 新建文章（或直接在 source/_posts/ 中新建 .md 文件）
npx hexo new "文章标题"

# 3. 本地构建与预览检查
npx hexo clean && npx hexo g && npx hexo s

# 4. 部署静态页面到线上网站（若配置了 hexo-deployer-git）
npx hexo d

# 5. 写作后：提交 Markdown 源码保存到 GitHub
git add .
git commit -m "feat: add new blog post"
git push origin main
